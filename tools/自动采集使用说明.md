# ROS + ULog 自动归档

适用：Ubuntu VM、现有 X500 SITL、`px4_control_experiment` v3 和 `px4_ab_mission` r9。只用 Python 3 标准库，不需重新编译 C++。

将 `run_px4_capture.py` 复制到 Ubuntu 的 `~/px4_tools/`。可先在 Ubuntu 普通终端执行 `mkdir -p ~/px4_tools`。

PX4/Gazebo、8888 通信桥和 `/clock` 桥保持运行，关闭 QGC Virtual Stick。本脚本会启动飞行任务；每次只运行一份任务节点。

## 1. PX4 终端（pxh>）

每次实验前执行，确认开始记录：

```text
logger on
logger status
```

若仍显示 `Not logging`，先解决记录问题，不要当成已经采集。

## 2. Ubuntu 普通 Bash 终端：启动一个科目

科目 1：

```bash
source /opt/ros/jazzy/setup.bash
source ~/px4_ros2_ws/install/setup.bash
python3 ~/px4_tools/run_px4_capture.py single_axis --output-root "$HOME/px4_experiments"
```

科目 2（与科目 1 分开运行）：

```bash
source /opt/ros/jazzy/setup.bash
source ~/px4_ros2_ws/install/setup.bash
python3 ~/px4_tools/run_px4_capture.py hover --output-root "$HOME/px4_experiments"
```

科目 3 A→DO_TASK→B 回归：

```bash
source /opt/ros/jazzy/setup.bash
source ~/px4_ros2_ws/install/setup.bash
python3 ~/px4_tools/run_px4_capture.py ab_mission --output-root "$HOME/px4_experiments"
```

要存到别处，只改 `--output-root` 后的目录。每次自动创建新目录，原始 PX4 ULog 保留。

## 3. 任务结束后

等待 ROS 输出“任务已完成：已回到 IDLE，飞机已落地并上锁”后，在运行脚本的终端按一次 Ctrl+C 结束已完成的 ROS 节点。节点最后一行 CSV 可能仍是 LANDING 过渡状态，这是正常的；`result.txt` 是任务完成标志。然后在 `pxh>` 执行：

```text
logger off
logger status
```

脚本最多等待 120 秒，检测日志关闭后自动复制，无需手动找路径。出现“采集归档完成”后，本次目录根下有：

```text
samples.csv
events.csv
result.txt
parameters.yaml
metadata.txt
flight.ulg
capture_manifest.json
capture.sha256
ros/                       原始完整与 agentdata 记录
```

脚本不采集 PX4 参数/版本快照，这两项仍应另外保存；采集完成也不代表飞行成功或数据质量通过。`result.txt` 保留实际成功/失败结果。

脚本比较启动前后的 ULog 清单，只有唯一新增或更新且已关闭的日志才自动归档。多个候选、没有结果或日志仍在写入时会报错，已生成的 ROS 数据保留。持续记录的 ULog 可能包含启动或多次飞行，分析时需分段。
